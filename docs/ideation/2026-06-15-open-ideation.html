Local AI Calendar Ideation

Ranked improvements and strategic directions for local LLM-constrained calendar automation

Grounding Context

This ideation is grounded directly in the codebase of alfred-macos-local-ai-calendar-workflow. The workflow contains the following key components:

  • main.swift: A native Swift helper wrapping EventKit to read and mutate events. Currently only supports basic fields: title, start date, end date, and calendar.
  • parse_query.ts: A TypeScript coordinator that routes the Alfred query to Ollama using schema-constrained grammar formats for low-latency JSON output.
  • execute_mutation.ts: A TypeScript file executing mutations via process spawning to the Swift binary.
  • info.plist: The Alfred workflow plist configuration controlling script filters and user text input.

The core constraint of the workflow is retaining the ~1.5-second execution speed while enhancing safety, capability, and ease of use.

1

Location, Notes, and URL Metadata Fields

Conf: 95% Cx: Low

Description: Expands the EventKit Swift binary's arguments and parse_query.ts schema constraints to support event locations, URLs, and descriptive notes. The local LLM will extract these parameters from strings like "Wed 9am client sync at Starbucks http://zoom.us" and apply them to the created calendar event.

Basis
direct:main.swift#L95-99 (Event save mechanism only binds core title, start, and end parameters, ignoring standard EventKit metadata properties).
Rationale
Capturing coordinates (locations, video links, notes) makes the parser fully comparable to proprietary services like Fantastical while retaining complete local data ownership.
Downsides
Extends the Ollama JSON schema property count, which could slightly increase parsing token counts, though in grammar-constrained modes this addition is negligible.
2

Recurrence Rules Support (EKRecurrenceRule)

Conf: 90% Cx: Medium

Description: Adds support for recurring events (e.g. "every Tuesday", "weekly sync"). The local model returns structured recurrence parameters (frequency, interval, end boundary) and `main.swift` uses `EKRecurrenceRule` to save these recurrence schedules in Apple Calendar.

Basis
direct:main.swift#L95-107 (No usage of EKRecurrenceRule; saved events are strictly one-shot instances).
Rationale
A significant portion of user events are recurring. Letting the local AI handle this reduces human calendar friction substantially.
Downsides
Implementing recurrence rules mapping from JSON keys (frequency, daily, weekly) to native EKRecurrenceRule objects in Swift introduces code complexity.
3

Offline Fallback Parser (Chrono-Node)

Conf: 85% Cx: Low

Description: Integrates a lightweight Javascript date parsing library like chrono-node into parse_query.ts. If Ollama is offline or takes too long to respond, the coordinator automatically falls back to regex-based natural language parsing to ensure the workflow is still usable.

Basis
direct:parse_query.ts#L96-106 (Strict single dependency on local port 11434 API generation; throws unhandled error if connection fails).
Rationale
If the Ollama process is sleeping, loading, or not started, the user faces workflow execution silence. A regex parser solves common relative date strings instantly with zero dependencies.
Downsides
Adds a package dependency (like chrono-node) to package.json, increasing the packaged .alfredworkflow zip bundle size.
4

Auto-Select Calendar by Event Semantics

Conf: 90% Cx: Low

Description: Updates the prompt guidelines in parse_query.ts to direct the LLM to select the most matching calendar name based on semantic analysis of the event title, rather than relying solely on slash parameters. E.g., "dentist appointment" automatically maps to the "Personal" calendar, while "sync with marketing team" routes to the work calendar.

Basis
direct:parse_query.ts#L21-27 (Hardcoded calendar mapping based on simple substring match rules on query input).
Rationale
Reduces manual typing friction for users since they don't have to remember to append /work or /personal tags to direct the event.
Downsides
The semantic classification requires the model to have clear reasoning about terms, which could have a margin of classification errors compared to explicit flags.
5

Create Apple Reminders Directly (EKReminder)

Conf: 80% Cx: Medium

Description: Expands the EventKit helper to manage reminders. If the user query starts with a reminder trigger (e.g. "todo buy groceries", "remind me to call John at 4pm"), the LLM flags the intent as `reminder` and the Swift helper creates an EKReminder instead of an EKEvent in the native Reminders app database.

Basis
direct:main.swift#L27 (Only queries and requests authorization for EKCalendar event types, completely ignoring EventKit's reminders database).
Rationale
Many quick capture notes are actually checklist items or reminders rather than scheduled calendar blocks. Providing a single unified search/add box for both increases utility.
Downsides
Requires requesting permission for both Events and Reminders from the user, which triggers a separate macOS permissions dialog.
6

Immediate Mutation with "Undo" Banner

Conf: 75% Cx: High

Description: Removes the multi-step confirmation phase in Alfred. The event is created in Apple Calendar immediately after hitting Enter. Simultaneously, a macOS desktop notification (or custom UI banner) is triggered with an "Undo" button. Clicking "Undo" invokes a delete command, making the interaction feel instant.

Basis
direct:info.plist (Workflow relies on a conditional path requiring user confirmation selection in Alfred).
Rationale
Saves an entire interaction step, making calendar entry feel immediate. An undo action serves as a safety net if the AI misinterprets the text.
Downsides
Requires integrating or triggering AppleScript notifications with actionable buttons, or writing a custom notification daemon in Swift.
7

Graceful Ollama Offline Error States

Conf: 95% Cx: Low

Description: Adds validation checks to parse_query.ts for the Ollama connection status. If a connection error occurs, instead of throwing an exception, output a formatted Alfred JSON item telling the user "Ollama Offline" with a subtitle guide on how to launch it.

Basis
direct:parse_query.ts#L102-105 (Fails abruptly with an API error message that halts execution).
Rationale
Prevents a bad user experience where the Alfred workflow appears broken, hanging, or prints developer debug traces.
Downsides
Requires minor code changes to wrap fetch operations in error-capturing handlers.

Rejection Summary

15 Unified CLI for Both Parsing and Mutation Separation between Swift and TypeScript is clean and easy to maintain.

21 Publisher-Subscriber Event Notifications No active use cases for custom event broadcasting.
22 Task Queue Pipeline for Bulk Queries Over-engineered for typical single-event entry use cases.

28 Full Calendar Browser in Alfred Bloats the script filter with UI presentation, deviating from minimalist launcher focus.
29 Ollama Cloud API Fallback Violates the strict offline, privacy-first design model of the workflow.
